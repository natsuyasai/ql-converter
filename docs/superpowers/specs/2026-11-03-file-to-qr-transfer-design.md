# File → QR 転送ツール 設計書

## 目的 (Why)
PC上の任意のファイル(想定: 数十KB程度)を、サーバー・ケーブル・専用アプリなしでスマホに渡したい。
PC画面に表示したQRコードをスマホのカメラで読み取るだけで、スマホ側でファイルが復元・保存できること。

## 全体像
3つの部品を、共通のコアモジュールで繋ぐ。すべてJavaScript。

1. **送信コア** (共通ライブラリ): ファイル → 圧縮 → 分割 → QRペイロード列
2. **送信ツール(2形態)**
   - ブラウザ版: GitHub Pages上の送信ページ。ファイルをドラッグ&ドロップ → QR画像を表示/PNG保存
   - Node.js CLI版: `node cli/make-qr.js <file> [-o out.png]` → PNG出力
3. **受信ページ**: GitHub Pages上の静的ページ。スマホのブラウザでカメラ起動 → QRを順不同で読み取り → 全部揃ったら復元してダウンロード

## ゴール
- 1枚のQRに収まるファイルはQR1枚、収まらなければ複数QRに分割する
- 複数QRは画像(PNG、A4相当)にまとめて出力する。1枚でQRが小さくなりすぎる場合は複数枚の画像に分ける
- 受信側は読み取り順不問・重複読み取り可。進捗(何枚中何枚)と未取得の番号が分かる
- 復元後、ファイル全体のハッシュ検証で正しさを確認してから保存できる
- 送信側・受信側ともサーバー不要、データは端末外に出ない
- GitHub Pages(HTTPS)でそのまま動く(カメラ利用にHTTPSが必要なため)

## 非ゴール
- 暗号化、パスワード保護
- 数百KB以上の大容量ファイル(上限を超えたら警告する。上限値は実装時に枚数/読み取り手間から決める)
- QR間の誤り訂正符号(欠けた分は再読み取りで補う)
- ネイティブアプリ化、双方向通信、スマホ→PC転送
- 結合画像のページ上の全QRを1回のカメラ撮影で一括読み取りすること

## アンチゴール(技術的には動いても失敗)
- 読み取りがシビアで、実際の画面表示から現実的に読み取れない(QRが細かすぎる等)
- 一部のQRを読み飛ばしたまま、壊れたファイルを保存してしまう
- 別のファイル(別転送)のQRが混ざっても気づかない

## 決まっている方針(ユーザー決定)
- 受信はWebページ(GitHub Pages)で行う
- ツール側もJavaScript
- 送信ツールはブラウザ版とNode CLI版の**両方**を提供する
- 標準カメラ/QRアプリの文字列だけに頼らない(バイナリは文字として壊れるため、Base64化して受信ページで復元)

## 設計の考え方(提案: Claudeの判断。変更可)
- **圧縮**: ファイルをzip(deflate)圧縮してから分割する(QR枚数削減のため)。圧縮しても小さくならない場合は無圧縮で送る旨をヘッダのフラグで示す。受信側は元のファイル名・内容を復元して保存する
- **ペイロード形式**: 各QRは1つのテキスト。ヘッダ(形式バージョン、転送ID、連番、総数、ファイル名、全体ハッシュ)+Base64データ。転送IDで別転送の混入を検出する
- **QRサイズ**: 画面表示+スマホカメラで安定して読める大きさと誤り訂正レベルを優先し、1QRあたりのデータ量は控えめにする。調整できるオプションを持たせる
- **結合画像**: グリッド状に並べ、各QRに「n/総数」を表示し、ファイル名・総数などのタイトルを付ける
- **結合画像のページ分割(ユーザー決定)**: 結合画像は常にA4相当のページサイズ(縦、比率210:297)を想定する。1ページに並べたQRが小さくなりすぎる(読み取りに必要な最小サイズを下回る)場合は、複数ページ(複数枚のPNG)に分けて出力する。最小サイズの閾値と1ページあたりの最大QR数は、実機での読み取りやすさを基準に実装時に決める(提案: 1ページ6〜12枚程度から調整)。各ページに「ページ n/m」と、各QRに通しの「n/総数」を表示する。出力は `out-1.png`, `out-2.png` … のような連番ファイル(ブラウザ版は各ページを順に表示し、個別/一括で保存できる)
- **読み取り運用**: A4ページ1枚を画面表示または印刷して、QRを1枚ずつ読み取る運用を前提とする。複数QRが同時に写っても読めるものは取り込む
- **ライブラリ**: QR生成・QR読み取り・zip(deflate)は既存の軽量ライブラリを使う。GitHub Pagesは外部CDNに依存しないよう同梱(vendoring)を優先
- **構成**: 共通コア(`src/`)をブラウザ版とCLI版が共有。Pages用ファイルはリポジトリ直下(`index.html`=送信, `receive.html`=受信)。変更可
- **テスト**: コアの往復テスト(ファイル→ペイロード列→復元で完全一致)、順不同/重複/欠損/別転送混入のケースをNodeで自動テスト

- ビルドツールの有無(なしを推奨。素のES modulesで動くなら尚良い)
